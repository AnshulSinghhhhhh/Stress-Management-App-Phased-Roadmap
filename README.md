# Stress Management App

A phased stress-management web app: detect stress, help in the moment, and — once the core loop is proven — go deeper into root causes and long-term skill-building.

> Ship the smallest loop that proves the app can detect stress and help in the moment. Earn the right to build deeper features based on real usage data, not assumptions.

## Stack
- **Backend**: FastAPI (Python)
- **Frontend**: React (TypeScript)
- **Database & Auth**: Supabase (Postgres + Auth, free tier — this is a $0 prototype)
- **Backend hosting**: Render (free web service)
- **Frontend hosting**: Vercel (free tier)
- **AI**: NVIDIA NIM (free tier, `build.nvidia.com`) for conversational check-ins/trigger probing; a separate deterministic, zero-cost keyword classifier for crisis-language detection that never depends on NIM being available (see `IMPLEMENTATION_PLAN.md` §0.4 — intentionally not LLM-only)

> ⚠️ This stack is chosen for $0 prototype cost, not production scale. Render's free tier sleeps after inactivity, Supabase's free project pauses if unused, and NVIDIA NIM's free tier is rate-limited with no SLA. Fine for a demo/prototype; revisit before real users depend on it.
- **Design**: Google Stitch, connected to the dev workflow via MCP

## Phases
1. **Phase 1 — MVP**: prove people will check in and find relief exercises useful. Includes the crisis pathway and data export/delete from day one (non-negotiable, not deferred).
2. **Phase 2 — Depth**: move from symptom relief to explaining *why* someone is stressed (trigger taxonomy, root-cause dashboard, personalization).
3. **Phase 3 — Long-term value**: skill-building courses, support circles, and a pathway to human support — the app becomes something people rely on for months.

Phase 2 does not start on a calendar date — it starts once Phase 1's success signal (multi-day return usage + weekly relief-exercise engagement) shows up in real data. Same logic gates Phase 3.

## Safety-critical component: the crisis pathway
Any check-in or manual trigger runs through crisis-language detection. If it fires, resources are shown **immediately, never gated behind login, never delayed by an AI call**. This logic, once built and reviewed in Phase 1, should not be modified without a dedicated safety review — see `SOP_ANTIGRAVITY.md` §6 before touching anything crisis-related.

Crisis resources currently configured for **India**:
- **Tele MANAS**: 14416 / 1-800-891-4416 (Govt of India, 24/7, multilingual)
- **KIRAN Mental Health Helpline**: 1800-599-0019 (Govt of India, 24/7)
- **Emergency**: 112

⚠️ Verify these numbers against official government sources before every production deploy — helpline numbers change.

## Privacy
- Conversational and biometric data encrypted at rest.
- No wearable integration required — the app is fully functional with zero wearables connected.
- Data export and deletion are real, working features from Phase 1, not deferred.
